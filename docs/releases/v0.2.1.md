garner 0.2.1 fixes three bugs in syncing from forges. Together they kept some sources from syncing anything, among them `open-telemetry/opentelemetry-collector-releases`, which now syncs without a token or extra configuration.

## Fixes

- A new source synced nothing when its repository's newest release had no assets matching the source's rules, as in repositories that publish several products as separate releases. Each poll waited for that release's assets and started over. A new source now starts from the newest release with matching assets. ([da40834](https://github.com/avesst/garner/commit/da40834))
- garner downloaded every checksum file in a release, though the forge's digest takes precedence over them. A release with hundreds of `*.sha256` files used up GitHub's unauthenticated limit of 60 requests an hour before any package was fetched, so the release was never synced. Checksum files are now downloaded only for packages without a forge digest, and a file named after another asset, such as `tool.deb.sha256`, only for that asset. A `checksums:` setting added to work around this can be removed. ([fc3b9c7](https://github.com/avesst/garner/commit/fc3b9c7))
- When the client for one forge could not be set up, for example because its `token_file` or `ca_file` was unreadable, no source synced, from any forge, and the only sign was one log line. Now only that forge's sources fail, with the error shown in `garner status` and the metrics, and a reload that fixes the file brings them back. ([386cb8b](https://github.com/avesst/garner/commit/386cb8b))

Full list of changes: https://github.com/avesst/garner/compare/v0.2.0...v0.2.1

garner is in early development and is not ready for internet-facing use. Configuration and behaviour may change between 0.x releases.
